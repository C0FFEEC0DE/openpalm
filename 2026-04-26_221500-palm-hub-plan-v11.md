## Protocol Stack Architecture (v11.0 — VERIFIED)

### Actual Stack from pilot-link (library-based)

```
Socket Layer (pi-socket.c: pi_socket_t with protocol stack)
  |
  +-- SLP (Serial Link Protocol)  [slp.c: 17459 bytes]
  |    Signature: 0xBE 0xEF 0xED, Header: 10 bytes, Footer: 2 bytes CRC-16
  |    Header checksum: sum(bytes 0-9) mod 0xFF
  |    CRC-16: CCITT 0x1021 applied to header+payload
  |
  +-- PADP (Pilot Application Protocol) [padp.c: 27274 bytes]
  |    Simple Ack/NACK: no tx_window, no reassembly
  |    Header: 4 bytes (type 1B + flags 1B + size 2B/4B)
  |    FL_FIRST: 0x80, FL_LAST: 0x40 (flags in byte 1)
  |    MTU: 1024 bytes (excluding header)
  |
  +-- DLP (Desktop Link Protocol) [dlp.c: 124797 bytes]
  |    Operations (conduits): Sync, ReadRecord, WriteRecord, etc.
  |    version() returns 0x0100, 0x0102, 0x0104, 0x0201
  |    Ex opcodes (DLP 1.4+): 0x5D-0x64 for >64KB records
  |
  +-- PDB/PRC File Format [pi-file.c: 38324 bytes]
  |    Header: 78 bytes + appInfo/sortInfo blocks
  |    Record entry: 8 bytes (offset 4B + attr 1B + uid 3B)
  |    next_record_list_id: header bytes 72-75
  |    Timestamp: PILOT_TIME_DELTA = 2082844800 (seconds 1904→1970)
  |
  +-- DLP RPC Timestamp Format [dlp.c]
  |    8 bytes: year(2B) + month(1B) + day(1B) + hour(1B) + min(1B) + sec(1B) + reserved(1B)
  |    Functions: dlp_ptohdate(), dlp_htopdate()
```

### Protocol Summary Table

| Layer | File | Size | Key Structures | CRC/Checksum |
|-------|------|------|----------------|--------------|
| **SLP** | slp.c | 17459 B | slp struct (header 10B + footer 2B) | CRC-16 CCITT 0x1021 |
| **PADP** | padp.c | 27274 B | padp_t (header 4B, MTU 1024B) | No CRC - simple length |
| **DLP** | dlp.c | 124797 B | dlp_req/resp, 100+ operations | No CRC - DLP layer only |
| **PDB** | pi-file.c | 38324 B | pi_file_t, records | No CRC - file format |

## Protocol Details (v11.0 — VERIFIED)

### 1. SLP Protocol (Serial Link Protocol)

**Header (10 bytes):**
```
Byte 0: 0xBE  (PI_SLP_SIG1)
Byte 1: 0xEF  (PI_SLP_SIG2)
Byte 2: 0xED  (PI_SLP_SIG3)
Byte 3: dest
Byte 4: src
Byte 5: type (0x00=RCVP, 0x02=PADP, 0x03=LOOP)
Byte 6-7: len (2B, big-endian)
Byte 8: txid
Byte 9: checksum (sum of bytes 0-9 mod 0xFF)
```

**Footer (2 bytes):**
```
Byte 10-11: crc16 (CCITT 0x1021) over bytes 0-9 + payload
```

**CRC-16 Implementation (from utils.c):**
```c
int crc16(unsigned char *ptr, int count) {
    int crc = 0;
    while (--count >= 0) {
        crc = crc ^ (int)*ptr++ << 8;
        for (i = 0; i < 8; ++i)
            if (crc & 0x8000)
                crc = crc << 1 ^ 0x1021;
            else
                crc = crc << 1;
    }
    return crc & 0xFFFF;
}
```

**Key Constants:**
```c
#define PI_SLP_HEADER_LEN 10
#define PI_SLP_FOOTER_LEN 2
#define PI_SLP_SIG_BYTE1 0xBE
#define PI_SLP_SIG_BYTE2 0xEF
#define PI_SLP_SIG_BYTE3 0xED
```

### 2. PADP Protocol (Pilot Application Protocol)

**Header (4 bytes, or 6 bytes if FL_LONG):**
```
Byte 0: type (padData=0x01, padWake=0x101, padAck=0x02, padTickle=0x04, padAbort=0x08)
Byte 1: flags (PADP_FL_FIRST=0x80, PADP_FL_LAST=0x40, PADP_FL_MEMERROR=0x20, PADP_FL_LONG=0x10)
Byte 2-3: size (SHORT format) OR
Byte 2-5: size (LONG format, if FL_LONG set)
```

**Key Constants:**
```c
#define PI_PADP_HEADER_LEN 4
#define PI_PADP_MTU 1024
#define PADP_FL_LONG 0x10   // 4-byte size instead of 2-byte
#define PADP_FL_FIRST 0x80  // First fragment (NOT 0x01)
#define PADP_FL_LAST 0x40   // Last fragment (NOT 0x02)
#define PADP_FL_MEMERROR 0x20 // Memory error on device

// Packet types
#define padData   0x01
#define padWake   0x101
#define padAck    0x02
#define padTickle 0x04
#define padAbort  0x08  // PalmOS 2.0 only
```

**PADP State Machine (pi_padp_data_t):**
```c
typedef struct pi_padp_data {
    int type;
    int last_type;
    int freeze_txid;
    int use_long_format;  // DLP 1.4+ sets this

    unsigned char txid;
    unsigned next_txid;

    unsigned char last_ack_txid;
    struct padp last_ack_padp;  // last received packet metadata
} pi_padp_data_t;
```

**No tx_window, no reassembly** - simple Ack/NACK with retry logic:
- PI_PADP_TX_TIMEOUT = 2000 ms
- PI_PADP_TX_RETRIES = 10
- PI_PADP_RX_BLOCK_TO = 30000 ms
- PI_PADP_RX_SEGMENT_TO = 30000 ms

### 2.5. CMP Protocol (Connection Management Protocol)

**Purpose:** Negotiates connection speed between Palm and desktop before HotSync.

**CMP Header (10 bytes):**
```
Byte 0: type (0x01=WAKE, 0x02=INIT, 0x03=ABRT, 0x04=EXTN)
Byte 1: flags
Bytes 2-3: version (big-endian, e.g., 0x0102)
Bytes 4-5: reserved
Bytes 6-9: baud rate (big-endian, e.g., 57600)
```

**CMP Constants (from pi-cmp.h):**
```c
#define PI_CMP_HEADER_LEN 10
#define PI_CMP_MTU        10

#define PI_CMP_TYPE_WAKE 0x01  // Wake up
#define PI_CMP_TYPE_INIT 0x02  // Initialize
#define PI_CMP_TYPE_ABRT 0x03  // Abort
#define PI_CMP_TYPE_EXTN 0x04  // Extended packet

#define PI_CMP_VERS_1_0 0x0100
#define PI_CMP_VERS_1_1 0x0101
#define PI_CMP_VERS_1_2 0x0102
#define PI_CMP_VERS_1_3 0x0103
#define PI_CMP_VERSION   PI_CMP_VERS_1_2

// Flags
#define CMP_FL_CHANGE_BAUD_RATE 0x80   // Request baud rate change
#define CMP_FL_USE_LONG_PACKET   0x40   // Use long packet format
#define CMP_FL_KEEP_CONNECTION   0x20   // Keep connection open
```

**CMP Handshake Flow:**
```
1. Desktop sends CMP_TYPE_WAKE (0x01)
2. Device responds with CMP_TYPE_INIT (0x02) + version + baud rate
3. Desktop acknowledges
4. Switch to negotiated baud rate (9600 → 57600+)
5. Proceed to SLP/PADP
```

### 2.6. NET Protocol (Network Protocol)

**Purpose:** Used for network-based HotSync (IrDA, Bluetooth, TCP/IP).

**NET Header (6 bytes):**
```
Byte 0: type (0x01=DATA, 0x02=TCKL/tickle)
Byte 1: txid
Bytes 2-3: size (big-endian)
Bytes 4-5: (unused?)
```

**NET Constants (from pi-net.h):**

### 3. DLP Protocol (Desktop Link Protocol)

**Version Detection:**
```c
// pi_version() returns:
// 0x0100 = DLP 1.0 (very old)
// 0x0102 = DLP 1.2 (Palm OS 4.x)
// 0x0104 = DLP 1.4 (Tapwave Zodiac)
// 0x0201 = DLP 2.1 (Palm OS 6 Cobalt)
```

**Default Version:**
```c
#define PI_DLP_VERSION_MAJOR 1
#define PI_DLP_VERSION_MINOR 4
#define PI_DLP_VERSION 0x0104  // Default for modern devices
```

**Ex opcodes (DLP 1.4+ for >64KB records):**
```
0x5D: dlpFuncExpSlotMediaType
0x5E: dlpFuncWriteRecordEx
0x5F: dlpFuncWriteResourceEx
0x60: dlpFuncReadRecordEx
0x61: dlpFuncUnknown1 (may be dlpFuncReadRecordStream)
0x62: dlpFuncUnknown3
0x63: dlpFuncUnknown4
0x64: dlpFuncReadResourceEx
```

**Large Record Handling:**
```c
if (dlp_version >= 0x0104) {
    // Use Ex opcodes for records >64KB
} else {
    // Reject or split records >64KB
}
```

```c
    ((unsigned char*)(ptr))[2] = ((val) >> 8) & 0xFF; \
    ((unsigned char*)(ptr))[3] = (val) & 0xFF; \
} while(0)

#define set_short(ptr,val) do { \
    ((unsigned char*)(ptr))[0] = ((val) >> 8) & 0xFF; \
    ((unsigned char*)(ptr))[1] = (val) & 0xFF; \
} while(0)

#define set_treble(ptr,val) do { \
    ((unsigned char*)(ptr))[0] = ((val) >> 16) & 0xFF; \
    ((unsigned char*)(ptr))[1] = ((val) >> 8) & 0xFF; \
    ((unsigned char*)(ptr))[2] = (val) & 0xFF; \
} while(0)

#define set_byte(ptr,val) do { \
    *((unsigned char*)(ptr)) = (val); \
} while(0)

// 4-char code creator/type (e.g., 'addr', 'DATA')
#define char4(c1,c2,c3,c4) (((c1)<<24)|((c2)<<16)|((c3)<<8)|(c4))
```

### 4. PDB/PRC File Format

**Header (78 bytes):**
```
Bytes 0-31:   name (32 bytes)
Bytes 32-33:  flags (2 bytes, big-endian)
Bytes 34-35:  version (2 bytes)
Bytes 36-39:  creation date (4 bytes, Palm timestamp — see below)
Bytes 40-43:  modification date (4 bytes)
Bytes 44-47:  backup date (4 bytes)
Bytes 48-51:  modification number (4 bytes)
Bytes 52-55:  appInfo offset (4 bytes)
Bytes 56-59:  sortInfo offset (4 bytes)
Bytes 60-63:  type (4 bytes, e.g. 'DATA')
Bytes 64-67:  creator (4 bytes, e.g. 'PAdd')
Bytes 68-71:  unique ID seed (4 bytes)
Bytes 72-75:  next record list id (4 bytes) ← CRITICAL: NOT in record entry
Bytes 76-77:  num records (2 bytes)
```

**Record Entry (8 bytes):**
```
Bytes 0-3:   offset (4 bytes, big-endian)
Byte 4:      attributes (1 byte)
Byte 5-7:    unique ID (3 bytes, big-endian)
```

### 5. Palm Timestamp Format (CORRECTED — v7)

**CORRECTED v7: Palm timestamps have TWO different formats**

There are **two different date formats** used in Palm OS:

#### Format A: 4-byte (PDB files and PILOT_TIME_DELTA)

PDB file header stores dates as **4-byte big-endian unsigned long** representing
**seconds since Palm epoch**: Fri Jan 1 00:00:00 1904 GMT.

**Palm Epoch constant:**
```
0x83DAC000 = Fri Jan 1 00:00:00 1904 GMT
```

**Conversion constants (from pi-file.c:109):**
```c
#define PILOT_TIME_DELTA (unsigned)(2082844800)
// PILOT_TIME_DELTA = seconds between Jan 1 1904 and Jan 1 1970 (Unix epoch)
```

**Conversion formulas:**
```c
// Palm timestamp → Unix time
time_t pilot_time_to_unix_time(unsigned long raw_time) {
    return (time_t)(raw_time - PILOT_TIME_DELTA);
}

// Unix time → Palm timestamp
unsigned long unix_time_to_pilot_time(time_t t) {
    return (unsigned long)(t + PILOT_TIME_DELTA);
}
```

#### Format B: 8-byte (DLP RPC calls via dlp_ptohdate/dlp_htopdate)

DLP uses an 8-byte structured format for date/time in RPC calls:

```
Bytes 0-1: year (big-endian, e.g., 0x07E5 = 2013)
Byte 2:    month (1-12)
Byte 3:    day (1-31)
Byte 4:    hour (0-23)
Byte 5:    minute (0-59)
Byte 6:    second (0-59)
Byte 7:    reserved (0)
```

**Conversion functions (from dlp.c:771-848):**
```c
// DLP date → Unix time (from dlp_ptohdate)
time_t dlp_ptohdate(const unsigned char *data) {
    // Returns 0x83DAC000 if date is empty (data[0]==0 && data[1]==0)
    struct tm t;
    memset(&t, 0, sizeof(t));
    t.tm_sec   = data[6];
    t.tm_min   = data[5];
    t.tm_hour  = data[4];
    t.tm_mday  = data[3];
    t.tm_mon   = data[2] - 1;
    t.tm_year  = (((int)data[0] << 8) | (int)data[1]) - 1900;
    t.tm_isdst = -1;
    return mktime(&t);
}

// Unix time → DLP date (from dlp_htopdate)
void dlp_htopdate(time_t time_interval, unsigned char *data) {
    time_t palm_epoch = 0x83DAC000;
    if (time_interval == palm_epoch) {
        memset(data, 0, 8);  // Empty date
        return;
    }
    struct tm *t = localtime(&time_interval);
    int year = t->tm_year + 1900;
    data[7] = 0;
    data[6] = t->tm_sec;
    data[5] = t->tm_min;
    data[4] = t->tm_hour;
    data[3] = t->tm_mday;
    data[2] = t->tm_mon + 1;
    data[0] = year >> 8;
    data[1] = year & 0xFF;
}
```

**Empty date sentinel:** `0x83DAC000` (Fri Jan 1 00:00:00 1904 GMT)

**Sync Algorithm (from sync.c):**

The sync algorithm handles these cases:
1. **New in Palm, deleted on PC** → Delete on Palm
2. **Deleted on Palm, new on PC** → Add to PC  
3. **Modified on Palm, deleted on PC** → Archive on Palm
4. **Deleted on Palm, modified on PC** → Undelete on Palm, update
5. **Modified on both** → Use conflict resolution callback
6. **Deleted on both** → No action
7. **Unchanged** → Skip

**Sync Flow:**
```
1. Call Pre() callback
2. For each desktop record:
   - Compare with Palm records using Match()
   - Determine sync action based on modified flags
   - Execute action (add/replace/delete/archive)
3. Call Post() callback
```

### Phase 1: `palm-protocol/` — Rust Port of Palm Protocols

#### Ключевые модули и исправления:

**`slp/` — исправлено:**
- Signature: **0xBE 0xEF 0xED** (3 байта)
- Header: **10 байт** (dest, src, type, len, txid, checksum)
- Footer: **2 байта** → CRC-16 CCITT (0x1021)
- Header checksum: **sum(bytes 0-9) mod 0xFF**
- CRC-16 applies to **entire frame**: header (10B) + payload

**`padp/` — исправлено:**
- Header: **4 байта** (type 1B + flags 1B + size 2B/4B)
- FL_LONG: **0x10** — size=2B ↔ 4B switch
- **No tx_window**: single txid with retry logic
- **No reassembly**: fragmented by FL_FIRST/**0x80**/FL_LAST/**0x40** flags
- MTU = 1024 bytes (excluding header)

**`dlp/` — исправлено:**
- `DlpVersion` enum: `V10 (0x0100)`, `V12 (0x0102)`, `V14 (0x0104)`, `V21 (0x0201)`
- **Default**: `DlpVersion::V14` (Tapwave Zodiac)
- Ex opcodes: **0x5D-0x64** (0x5D=ExpSlotMediaType, 0x5E=WriteRecordEx, 0x5F=WriteResourceEx, 0x60=ReadRecordEx, 0x61=Unknown1, 0x62=Unknown3, 0x63=Unknown4, 0x64=ReadResourceEx)
- Large records: `if dlp_version >= 0x0104 && record_size > 0xFFFF { use_ex_opcode() }`

**`pdb/` — исправлено:**
- Header: **78 байт** (name 32B + flags 2B + version 2B + dates 16B + modno 4B + appinfo 4B + sortinfo 4B + type 4B + creator 4B + seed 4B + next_record_list_id 4B + nrecords 2B)
- Record entry: **8 байт** (offset 4B + attributes 1B + unique_id 3B)
- `next_record_list_id`: байты 72-75 header (не record entry!)
- Record attributes: `dlpRecAttrDeleted (0x80)`, `dlpRecAttrDirty (0x40)`, `dlpRecAttrBusy (0x20)`, `dlpRecAttrSecret (0x10)`, `dlpRecAttrArchived (0x08)`

**`usb/` — исправлено (v6):**
```
Sony (0x054c): 0x0038, 0x0066, 0x0095, 0x000a, 0x009a, 0x00da, 0x00e9, 0x0144, 0x0169
Handspring (0x082d): 0x0100 (Visor/Treo 300), 0x0200 (Treo), 0x0300 (Treo 600)
PalmOne (0x0830): 0x0001 (m500) ... 0x0100 — full table
Tapwave (0x12ef): 0x0100 (Zodiac/Zodiac2) ← USB_INIT_TAPWAVE
AlphaSmart (0x081e): 0xdf00 (Dana)
Garmin (0x091e): 0x0004 (IQUE 3600)
Kyocera (0x0c88): 0x0021 (7135), 0xa226 (6035)
Aceeca (0x4766): 0x0001 (MEZ1000)
Samsung (0x04e8): 0x8001 (i330)
```
- Init flags: USB_INIT_NONE, USB_INIT_TAPWAVE, USB_INIT_VISOR, USB_INIT_SONY_CLIE
- Control requests: GENERIC_REQUEST_BYTES_AVAILABLE (0x01), VISOR_GET_CONNECTION_INFORMATION (0x03), PALM_GET_EXT_CONNECTION_INFORMATION (0x04)

**`utils/` — исправлено (v7):**
- **PalmDate: TWO formats**
  - **Format A (4B):** PDB files — секунды с 1904 года, PILOT_TIME_DELTA = 2082844800
  - **Format B (8B):** DLP RPC — dlp_ptohdate/htopdate: year(2B) + month(1B) + day(1B) + hour(1B) + min(1B) + sec(1B) + reserved(1B)
- **PILOT_TIME_DELTA**: **2082844800** (секунды между 1904 и 1970)
- **Epoch**: 0x83DAC000 (Fri Jan 1 00:00:00 1904 GMT)
- **CRC-16 CCITT**: `0x1021`, init = 0
